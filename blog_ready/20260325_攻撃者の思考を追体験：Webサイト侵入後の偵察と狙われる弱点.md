今日のテーマ：侵入の入り口を見つけたあと、攻撃者は何を見て、どこを目指すのか。
セキュリティの知識を深めながら、攻撃者の思考回路を追体験してみましょう。

### 攻撃者は入り口を見つけた後、まず何を確認するのか

**セキュリティスペシャリスト**: さて、今日は「侵入の入り口」を見つけた後の世界を想像してみましょう。IPアドレスとポート番号を特定し、Webサイトという窓口を見つけたとします。さて、あなたならそこからどんな手順で中を覗き込もうと考えますか？

**セキュリティ初学者**: うーん、まずはWebサイトのファイル構成を調べようとすると思います。インデックスファイル（index.htmlなど）からリンクをたどって、どんなファイルが置かれているのか、ディレクトリの構造を把握するんじゃないかなって。宝探しみたいに、隠されたファイルや設定ファイルが見つかれば、そこから何かがわかるはずだと思ってます。

**セキュリティスペシャリスト**: なるほど、それは「偵察（Reconnaissance）」の第一歩として非常に論理的です。ただ、実際の攻撃者は「ファイル一覧」を眺めるよりも、もっと効率的で「意味のある場所」を探しています。

例えば、Webサイトの裏側にある「設定ファイル」や「バックアップファイル」を狙うケースが多いですね。過去には、`.git`ディレクトリが公開設定のままになっていて、ソースコードが丸ごとダウンロードされてしまった事件がありました。攻撃者はファイル構造を全部なぞるのではなく、Webサーバーの設定ミスを突いて「本来見えてはいけない裏側の情報」を一気に引き抜こうとするんです。もしあなたがサーバー管理者なら、公開ディレクトリに置くべきではないファイルが、うっかり残っていないか確認する重要性がわかりますよね？

**セキュリティ初学者**: なるほど……全部を順番に見ていくわけじゃないんですね。確かに、ソースコードそのものが手に入ったら、その中身を読んでさらに深い弱点を見つけられそうです。でも、侵入できたとして、その先に何を狙うのかがまだぼんやりしています。そこからどこへ向かうんでしょうか？

**セキュリティスペシャリスト**: 鋭い視点です。では、侵入後の動きについて深掘りしましょう。侵入した先がゴールではないとしたら、攻撃者は次に何を「宝」として設定すると思いますか？

**セキュリティ初学者**: やっぱり、一番大事なデータがある場所……例えばユーザーの個人情報が入っているデータベースとか、管理者権限のIDとパスワードが書いてある場所を目指すんじゃないでしょうか。そこまでたどり着けば、このサイトを乗っ取ったと言える気がします。

**セキュリティスペシャリスト**: その通りです。攻撃者は「権限の昇格（Privilege Escalation）」を常に狙っています。最初は一般ユーザー権限で侵入しても、サーバー内の設定ファイルから管理者のパスワードを盗み出し、システム全体をコントロールしようとします。

実際、ある企業でWebサーバーの脆弱性が突かれ、そこを足掛かりに社内ネットワークへ侵入された事例があります。攻撃者はWebサイトを改ざんするだけでなく、社内のデータベースへ接続するための資格情報（ID/パスワード）を盗み出し、最終的に顧客情報を大量に流出させました。つまり、Webサイトは単なる「ゴール」ではなく、より大きなネットワークへ侵入するための「踏み台」に過ぎない場合があるのです。侵入者は「ここからどこに繋がっているか？」というネットワークの地図を、侵入後に作り上げているのですよ。

## 技術メモ

### [1] 攻撃の種類
Webサイトやサーバーへの侵入・偵察に関連する主な攻撃手法です。

| 種類名 | 特徴 | 主なリスク |
| :--- | :--- | :--- |
| ディレクトリトラバーサル | 本来アクセスできない階層へ移動する | 機密ファイルの閲覧・流出 |
| 設定ミス（Misconfiguration） | 公開不要なファイルやバックアップの放置 | ソースコード流出・システム解析 |
| 権限昇格攻撃 | 一般権限から管理者権限を奪取する | システムの完全な掌握・破壊 |

### [2] コード例（学習用・悪用不可）
**攻撃のイメージ（ファイル探索）:**
攻撃者は自動化ツールを使い、以下のような推測されるパスへアクセスを試みます。
```html
<!-- 攻撃者が試すパスの例 -->
/admin/config.php
/.env
/.git/config
/backup.sql
```

**防御側の対策例（Python/Flaskでのアクセス制限）:**
特定のディレクトリへのアクセスを拒否する設定の概念です。
```python
from flask import Flask, abort

app = Flask(__name__)

# 特定の機密ディレクトリへのアクセスを拒否する
@app.before_request
def block_hidden_files():
    if request.path.startswith('/.git') or request.path.endswith('.env'):
        abort(403) # 403 Forbiddenを返す
```

### [3] 防御の実装チェックリスト
- [ ] 不要なファイル（.git, .env, .bakなど）を公開ディレクトリに置かない
- [ ] Webサーバーの設定でディレクトリリスティング（一覧表示）を無効にする
- [ ] 最小権限の原則に基づき、Webアプリの実行ユーザーに過度な権限を与えない
- [ ] データベースへの接続情報などの機密情報は環境変数で管理する
- [ ] 定期的な脆弱性スキャンを行い、設定ミスがないか確認する
- [ ] 侵入検知システム（IDS/IPS）を導入し、異常なアクセスパターンを監視する
- [ ] 管理画面へのアクセスを特定のIPアドレスからのみに制限する

### 今日のまとめ

*   **偵察は効率が命**: 攻撃者はすべてのファイルを順番に調べるのではなく、設定ミスや機密情報が漏れやすい「特定の場所」をピンポイントで狙います。
*   **Webサイトは踏み台になる**: 侵入の成功はゴールではなく、社内ネットワークやデータベースへアクセスするための「入り口」として利用されるリスクがあります。
*   **権限昇格を警戒する**: 最初の侵入権限は低くても、サーバー内の情報を盗んで管理者権限を奪い取ろうとする動きが非常に危険です。
*   **防御の基本は「見せない」**: 公開すべきでないファイルはそもそもWebサーバーの公開領域に置かない、という物理的な分離が最も強力な防御になります。
