今日のテーマ：身近に潜む「サービス停止」の脅威、DoS攻撃とDDoS攻撃の仕組みを紐解く。

### サービスをダウンさせる攻撃の「重み」を理解する

**セキュリティスペシャリスト**: さて、今日は「サービスを動かなくさせる攻撃」について深掘りしていきましょう。DoS攻撃やDDoS攻撃という言葉はニュースでもよく聞きますが、具体的に何が起きているのか、まずはあなたのイメージを教えてもらえますか？

**セキュリティ初学者**: はい！なんとなくですが、たくさんのアクセスを送りつけてサーバーをパンクさせる攻撃かなと思っています。DoSとDDoSの違いは、攻撃元が「1つ」か「複数」かという点ですよね？ただ、最近だとDRDoS攻撃とか、リソースを消費する攻撃とか、専門用語が増えてきて正直こんがらがっています。

**セキュリティスペシャリスト**: 鋭いですね。その認識は非常に正確です。DoS（Denial of Service）は「サービス拒否」、DDoS（Distributed DoS）は「分散型」のサービス拒否攻撃を指します。攻撃者が自分のPCから攻撃するのではなく、世界中に散らばったウイルス感染済みのPC（ボットネット）を一斉に操って、標的のサーバーへ同時に大量の通信を送りつけるのがDDoSです。

例えば2016年、DNSサービスを提供するDyn社が大規模なDDoS攻撃を受け、TwitterやNetflixなど大手サービスが軒並みアクセス不能になった事件がありました。これは「Mirai」というマルウェアに感染したIoT機器（防犯カメラやルーターなど）が数百万台規模で一斉に攻撃に加担したことで起きたものです。単なる「数」の暴力に見えますが、現代ではIoTデバイスが踏み台にされることで、攻撃の規模が桁違いに増大しているのが怖いところですね。

**セキュリティ初学者**: 防犯カメラやルーターが攻撃の武器になっていたなんて驚きです。でも、ただ通信をたくさん送るだけなら、サーバーの回線を太くすれば防げるような気もするのですが、それだけでは足りないのでしょうか？

**セキュリティスペシャリスト**: 良い疑問です。では、次のステップとして「なぜ回線を太くするだけでは防げないのか」という点をもっと深く考えてみましょう。攻撃者はただ「量」で攻めるだけではないとしたら、他にどんな攻撃手法があると思いますか？

**セキュリティ初学者**: うーん、量以外だと……例えば、すごく複雑な計算が必要なリクエストをわざと大量に送って、サーバーの頭脳（CPU）を忙しくさせるとかでしょうか？あとは、ネットワークの決まり事の隙を突くような攻撃もある気がします。

**セキュリティスペシャリスト**: その通りです！それを「アプリケーション層攻撃」や「プロトコル攻撃」と呼びます。回線を太くする「ボリューメトリック攻撃」は確かに力技ですが、あなたの言う通り、サーバーのCPUやメモリを枯渇させる手法は非常に厄介です。

例えば、Webサイトのログイン画面で、非常に重い検索処理を何度も実行させるようなリクエストを送れば、少ない通信量でもサーバーは悲鳴を上げます。また、TCPという通信のルールには「スリーウェイ・ハンドシェイク」という手順があるのですが、攻撃者は「接続を始めます！」という挨拶だけ送って、その後の返事（ACK）をわざと無視し続けます。すると、サーバー側は「返事が来るはずだ」と待ち続けてしまい、他の正規のユーザーを受け入れるための「待ち行列」がすぐに満杯になってしまうんです。これをSYNフラッド攻撃と言います。つまり、回線が空いていても、サーバーの「処理能力」や「接続枠」が先に限界を迎えてしまうのですね。

**セキュリティ初学者**: なるほど！通信量で押しつぶすだけじゃなくて、サーバーのルールとか仕組みの弱点を突いて「忙しいフリ」をさせるような攻撃もあるんですね。それだと、どんなに高性能なサーバーでも、攻撃者が賢いと耐えられない気がして怖いです。

**セキュリティスペシャリスト**: まさにその通りです。だからこそ、セキュリティ対策は「多層的」である必要があります。ネットワークの入り口で怪しい通信を捨てるだけでなく、サーバー内部でも「このユーザーは短時間に何回も重い処理をしているな」と検知して遮断したり、通信そのものの正当性を厳しくチェックしたりする必要があるのです。

## 技術メモ

### [1] 攻撃の種類

| 種類名 | 特徴 | 主なリスク |
| :--- | :--- | :--- |
| ボリューメトリック攻撃 | 大量のパケットを送り帯域を埋め尽くす | ネットワーク回線の飽和によるサービス停止 |
| プロトコル攻撃 | 通信手順の不備や仕様を悪用する | OSやネットワーク機器のリソース枯渇 |
| アプリケーション層攻撃 | 重い処理を要求しCPUやメモリを消費させる | データベースやアプリの応答不能 |

### [2] コード例（学習用・悪用不可）

**攻撃ペイロード（概念図：SYNフラッド）**
```python
# 攻撃者はSYNパケットを大量に送信し、ACKを返さない
import socket
target_ip = "192.168.1.1"
target_port = 80
# 実際にはソケットを大量に生成し、接続を「半開き」状態にする
```

**防御側：リクエスト制限（Flaskを用いた簡易実装）**
```python
from flask import Flask, request, abort
from flask_limiter import Limiter

app = Flask(__name__)
# 1分間に10回以上のアクセスを制限する（レートリミット）
limiter = Limiter(app, key_func=lambda: request.remote_addr)

@app.route("/search")
@limiter.limit("10 per minute")
def search():
    # 検索処理
    return "検索結果"
```

### [3] 防御の実装チェックリスト
- [ ] WAF（Web Application Firewall）を導入し、異常なリクエストを遮断する
- [ ] レートリミット（一定時間内のアクセス回数制限）を実装する
- [ ] 不必要なポートやサービスを閉じて攻撃対象を減らす
- [ ] SYN CookieなどのOSレベルの防御機能を有効にする
- [ ] CDN（コンテンツ配信ネットワーク）を利用して攻撃を分散・吸収する
- [ ] 負荷分散装置（ロードバランサー）で不正なトラフィックをフィルタリングする
- [ ] 監視体制を整え、異常なトラフィック増加を即座に検知する

### 今日のまとめ
- DoS攻撃は単一の攻撃元からの妨害、DDoS攻撃は多数の踏み台を利用した大規模な妨害を指します。攻撃元を特定しにくいDDoSは特に防ぐのが困難です。
- 攻撃は「通信量で回線を埋める手法」だけでなく、「サーバーの処理能力を枯渇させる手法」や「通信ルールの隙を突く手法」など多岐にわたります。
- どんなに高性能なサーバーでも、ソフトウェアやネットワークの設計次第でダウンさせられる可能性があります。多層的な防御を組み合わせることが、サービスを守る鍵となります。
