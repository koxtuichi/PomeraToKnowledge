今日のテーマ：サイバー攻撃の第一歩「偵察」とは何か。
攻撃者がターゲットを見つけ出すための、リアルな手法と仕組みを紐解きます。

### 攻撃者はどうやって獲物を探しているのか

**セキュリティスペシャリスト**：こんにちは！今日は「サイバー攻撃の入り口」とも言える、偵察フェーズについて考えてみましょう。あなたは、攻撃者がどうやって攻撃対象のサーバーやPCを見つけていると思いますか？

**セキュリティ初学者**：こんにちは！そうですね……攻撃者はIPアドレスをランダムに作って、それをプログラムでひたすら投げ続けているんじゃないでしょうか。例えばbashスクリプトとかを使って、pingコマンドみたいに「そこに誰かいますかー？」って送って、返事があったら「よし、ここに獲物がいる！」ってメモしていくようなイメージです。ネットワークの外から適当にバケットを送りまくれば、どこかしらで応答があるはずですよね。

**セキュリティスペシャリスト**：なるほど、それは非常に論理的な推測ですね。実際に「ポートスキャン」と呼ばれる手法では、まさにそうしたアプローチがとられます。ただ、今の攻撃者はもっと賢くて、ただランダムにpingを打つだけでは効率が悪すぎることを知っています。

例えば、攻撃者は「Shodan（ショーダン）」というツールをよく使います。これはインターネットに繋がっている機器を常に検索し、データベース化している検索エンジンです。攻撃者はわざわざ自分でIPを打ち続けなくても、このツールで「特定の脆弱なOSを使っている機器」や「ログイン画面が露出しているカメラ」を検索するだけで、一瞬でターゲットを見つけ出せてしまうんです。実際に、古い設定のまま放置されたIoT機器がこのツール経由で検索され、ボットネット（攻撃者の操り人形にされたネットワーク）に組み込まれる事件は後を絶ちません。闇雲に総当たりするよりも、地図を広げて獲物を探す方が圧倒的に早いということですね。

**セキュリティ初学者**：えっ、自分で頑張ってスクリプトを書かなくても、そんな便利な検索エンジンがあるんですか？ それじゃあ、適当に送るよりもずっと効率がいいですね……。でも、もしそうやってIPアドレスを見つけられたら、次はどんなことをしてくるんでしょうか？

**セキュリティスペシャリスト**：鋭い質問です。獲物を見つけた攻撃者は、次に「その中身」を覗こうとします。IPアドレスがわかったら、次は「どの扉が開いているか」を確認するんです。あなたは、サーバーの「扉」って何のことだと思いますか？

**セキュリティ初学者**：扉……ですか？ 鍵がかかっている場所ってことですよね。ウェブサイトを見るためのポートとか、遠隔操作するためのポートとか、そういうのが関係している気がします。でも、そういうのは普通、鍵がかかっていて簡単には入れないようになってるんじゃないですか？

**セキュリティスペシャリスト**：その通りです。その「扉」が「ポート」です。サーバーには0から65535までのポート番号が割り振られていて、それぞれ役割が違います。Webなら80番や443番、遠隔操作なら22番といった具合です。

攻撃者は「nmap」という有名なツールを使って、ターゲットのサーバーでどのポートが開いているかを調べます。たとえば、本来なら閉じておくべき「管理用のポート」が開いていれば、「ここは設定ミスをしている可能性があるぞ」と判断し、そこを重点的に攻撃するのです。実際に起きた事件では、管理者が検証用に一時的に開けていたポートを攻撃者に見つけられ、そこから侵入を許して顧客情報が流出したケースが多々あります。攻撃者にとって、ポートが開いていることは「鍵をかけ忘れた家」を見つけるのと同義なんです。

**セキュリティ初学者**：なるほど……。開いているポートを調べるだけで、そんなに弱点が見えてしまうんですね。じゃあ、自分のサーバーを守るためには、まずは「不要なポートを閉じる」ことが一番の防御になるってことでしょうか？

**セキュリティスペシャリスト**：大正解です！「不要なものは動かさない、開けない」。これがセキュリティの鉄則です。偵察されることを前提に、いかに相手に「ここは硬そうだから、別の獲物を探そう」と思わせるかが重要になります。

## 技術メモ

### 攻撃の種類

| 種類名 | 特徴 | 主なリスク |
| :--- | :--- | :--- |
| **Ping掃引** | ICMPパケットで稼働確認を行う | ネットワーク内の生存ホストの特定 |
| **ポートスキャン** | TCP/UDPのポートの応答を確認 | 稼働サービスとOSの特定・脆弱性調査 |
| **OS・サービス指紋抽出** | バナー情報などでソフトの種類を特定 | 既知の脆弱性（CVE）を狙った攻撃の準備 |

### コード例（学習用・悪用不可）

**攻撃側（nmapによるポートスキャン例）**
```bash
# ターゲットのIPに対し、よく使われる1000個のポートをスキャン
nmap -F 192.168.1.1
```

**防御側（Pythonによるファイアウォール設定の考え方）**
```python
# 必要なポート以外を拒否するiptables設定の概念
import os

def secure_server():
    # 許可するポートのみを開放し、他をブロックする
    allowed_ports = [80, 443]
    for port in allowed_ports:
        os.system(f"iptables -A INPUT -p tcp --dport {port} -j ACCEPT")
    
    # デフォルトで全て拒否
    os.system("iptables -P INPUT DROP")
```

### 防御の実装チェックリスト
- [ ] 不要なサービス・プロセスを停止する
- [ ] ファイアウォールで必要なポート以外をすべて閉じる（デフォルト拒否）
- [ ] サーバーのバナー情報（バージョン情報など）を隠蔽する
- [ ] Shodan等で自社ドメイン/IPが露出していないか定期的に確認する
- [ ] IDS/IPS（侵入検知・防御システム）を導入し、異常なスキャンを検知する
- [ ] SSHなど管理用ポートへのアクセス元をIP制限する

### 今日のまとめ

*   **偵察は効率化されている**: 攻撃者はランダムな総当たりだけでなく、Shodanのような検索エンジンを活用して、脆弱なターゲットを効率的に選別しています。
*   **ポートは「家の扉」である**: サーバー上の不要なポートが開いていることは、泥棒に対して「ここから入れます」と看板を出しているようなもので、非常に危険です。
*   **防御の基本は「最小化」**: 不要なポートを閉じ、余計なサービスを動かさないという「ミニマリズム」こそが、偵察フェーズで攻撃者を諦めさせる最大の武器になります。
